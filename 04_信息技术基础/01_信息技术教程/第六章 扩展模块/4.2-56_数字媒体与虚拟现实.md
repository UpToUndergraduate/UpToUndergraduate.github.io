# 6.9 数字媒体与虚拟现实

> **考纲对应**：数字媒体 第 1~8 条——理解数字媒体与数字媒体技术的概念；了解发展趋势；了解数字文本、数字图像、数字声音、数字视频的处理过程；了解 HTML5 新特性并掌握应用制作与发布；了解虚拟现实的概念、历程、应用与趋势（层次：理解、了解、掌握）
> **教材对应**：单元 16 数字媒体、单元 17 虚拟现实

数字媒体是扩展模块中"技术过程最具体"的一节：文本、图像、声音、视频四类媒体各有自己的数字化路径，考试常以"某一步骤属于哪个环节""某格式是有损还是无损""数据量怎么算"的形式出现。虚拟现实则偏概念与辨析，重点在"3I 特征"与 VR、AR、MR 的区分。把"采集—处理—压缩—存储—发布"这条主线贯穿全节，零散的知识点就能串成一条链。

## 一、数字媒体与数字媒体技术

**媒体**在信息技术中指承载与传递信息的载体。**数字媒体**是以二进制数字形式表示、存储、处理和传播的媒体信息，包括数字文本、数字图形图像、数字声音、数字视频与动画等。**数字媒体技术**则是研究这些媒体信息的获取、编码压缩、编辑处理、存储管理、传输分发与呈现交互的技术体系。

与传统模拟媒体相比，数字媒体具有**可无损复制、易编辑修改、便于压缩与网络传输、可交互、可实现多媒体集成**等特点。其发展趋势是：内容生产智能化（AI 生成图文音视频）、交互方式自然化（语音、手势、眼动）、呈现形态沉浸化（VR/AR）、传播渠道社交化与个性化推荐、制作工具云端化与轻量化。

## 二、数字文本处理

数字文本的处理过程可概括为"**录入—编辑—排版—存储—检索**"。

| 环节 | 主要工作与技术 |
|---|---|
| 录入 | 键盘输入、手写识别、光学字符识别（OCR）、语音识别 |
| 编辑 | 增删改、查找替换、拼写与语法检查、批注修订 |
| 排版 | 字体字号、段落样式、图文混排、目录与页码、样式模板 |
| 存储 | 以字符编码表示，常见编码有 ASCII、GB 系列国标编码、Unicode（UTF-8 等）；常见格式有 TXT、DOCX、PDF、HTML |
| 检索 | 关键词检索、全文检索、布尔逻辑与通配符 |

其中 PDF 适合版式固定的分发场景，DOCX 适合需要继续编辑的场景，HTML 适合网页发布。字符编码不一致是中文乱码的根源，跨平台交换文本应统一使用 Unicode 编码。

## 三、数字图像处理

数字图像由**像素**按行列排成矩阵，每个像素用若干位记录颜色，位深决定可表示的颜色数。处理过程为：**采集 → 预处理 → 处理与分析 → 压缩 → 存储 → 检索**。

- **采集**：数码相机、手机摄像头、扫描仪、屏幕截图。
- **去噪**：消除传感器噪声与压缩伪影，常用均值滤波、中值滤波、高斯滤波。
- **增强**：改善视觉效果，如调整对比度与亮度、直方图均衡、锐化，使细节更清晰。
- **复制**：对图像区域进行拷贝、仿制与修补，用于去除瑕疵或合成内容（如仿制图章）。
- **分割**：按颜色、边缘或区域把图像划分为若干有意义的子区域，如抠图、医学影像中的器官分离。
- **提取特征**：提取边缘、角点、纹理、颜色直方图等，为识别与检索提供依据，人脸识别即依赖特征提取。
- **压缩**：无损压缩（如 PNG、GIF 的部分模式）可完全还原；有损压缩（如 JPEG）舍弃部分视觉冗余以换取高压缩比。
- **存储**：BMP 无压缩体积大，JPEG 适合照片，PNG 支持透明、适合图形与截图，TIFF 常用于印刷与出版。
- **检索**：除按文件名与标签检索外，还可基于内容检索（CBIR），用颜色、纹理、形状特征找相似图片。

> 关键提醒：去噪与增强都是**预处理**手段，去噪的目的是抑制干扰，增强的目的是突出有用信息，二者常配合使用，不可相互替代。

## 四、数字声音与移动端音频制作

### 1. 数字声音的特点

声音是声波引起的空气振动，属于**模拟信号**，在时间和幅度上都是连续的。人耳可听频率范围约为 20 Hz 至 20 kHz。声音的三要素是**音调**（由频率决定）、**音色**（由波形与谐波成分决定）、**音量**（由振幅决定）。数字声音则由离散的采样点序列表示，便于存储、编辑与网络传输，但会产生量化误差。

### 2. 声音的数字化过程

声音数字化分三步，顺序不可颠倒：

1. **采样**：按固定时间间隔读取模拟波形的幅度值，每秒采样次数称为**采样频率**。采样频率越高，还原越真实，常用的有 44.1 kHz、48 kHz。
2. **量化**：把每个采样点的幅度值归入有限个离散等级，等级数由**量化位数**决定（如 8 位、16 位、24 位）。位数越多，精度越高，量化噪声越小。
3. **编码**：把量化后的数值按一定规则表示为二进制数据，并可进一步压缩（如 MP3、AAC 采用有损压缩，FLAC 为无损压缩）。

未压缩音频的数据量可按公式估算：**数据量 = 采样频率 × 量化位数 × 声道数 × 时长 ÷ 8**（单位：字节）。

### 3. 移动端录制、剪辑与发布

手机录制音频通常由系统录音应用或第三方 App 完成：选择采样率与声道（语音用单声道低采样率即可，音乐用双声道高采样率）→ 录制并保存为 WAV/MP3/M4A → 在剪辑 App 中裁剪、降噪、调整音量与淡入淡出、拼接配乐 → 导出为通用格式 → 发布到播客平台、社交平台或学习平台。

**例 6.9-1** 一段时长为 10 秒的双声道音频，采样频率 44.1 kHz、量化位数 16 位、未压缩，其数据量约为（　）。

A. 约 0.17 MB　B. 约 1.76 MB　C. 约 17.6 MB　D. 约 176 MB

**解**

1. 代入公式：44100 × 16 × 2 × 10 ÷ 8 = 1 764 000 字节。
2. 换算：1 764 000 ÷ 1024 ÷ 1024 ≈ 1.68 MB，按 1000 进制换算约 1.76 MB，与 B 最接近。
3. 故选 B。若误按单声道计算会得到约 0.88 MB，若漏除 8 则会放大 8 倍，这两个都是常见错误选项的来源。

- **易错点**：①漏乘声道数，双声道数据量是单声道的两倍；②忘记把"位"换算为"字节"而漏除以 8；③把采样频率与量化位数的作用混淆，前者决定时间方向的精细度，后者决定幅度方向的精细度。

## 五、数字视频处理

数字视频由**连续的画面帧**按时间顺序排列组成，利用人眼的**视觉暂留**形成运动感。基本参数包括**分辨率**（如 1920×1080）、**帧率**（每秒帧数，常见 24、25、30、60 帧）、**码率**（单位时间数据量）、**色彩深度**。

处理过程为：**采集 → 剪辑 → 特效与字幕 → 音频处理 → 压缩编码 → 输出发布**。

- **采集**：摄像机、手机、屏幕录制、动画渲染。
- **剪辑**：按时间线裁剪片段、调整顺序、分割与合并。
- **特效与字幕**：转场、滤镜、调色、关键帧动画、字幕与角标。
- **压缩编码**：视频数据量极大，必须压缩。MPEG 系列与 H.264、H.265 通过帧内压缩与帧间运动补偿大幅降低码率；H.265 相比 H.264 在同画质下码率更低。
- **封装输出**：常见容器格式有 MP4、AVI、MOV、MKV，其中 MP4 兼容性最好，适合网络分发。

**例 6.9-2** 某教师要把 40 分钟的课堂录像上传到网络教学平台，希望画质尚可、文件尽量小、各类设备都能播放。下列做法最合理的是（　）。

A. 直接上传未压缩的原始录像
B. 用 H.264 或 H.265 编码压缩，封装为 MP4 后上传
C. 把视频逐帧导出为 BMP 图片再上传
D. 只保留视频、删除所有音轨以减小体积

**解**

1. 需求是"体积小 + 兼容性好 + 画质可接受"，必须在压缩效率与兼容性之间取平衡。
2. H.264/H.265 是主流高效编码，MP4 容器兼容性最好，故选 B。
3. A 原始录像体积极大，上传与播放都不现实；C 丢失时间信息，无法作为视频播放；D 破坏教学内容完整性。

- **易错点**：①把编码格式与封装格式混为一谈，H.264 是编码，MP4 是容器，同一容器可装不同编码；②认为压缩比越高越好，过度压缩会造成明显块效应与拖影。

## 六、HTML5 应用的新特性与制作发布

HTML5 是新一代网页标准，主要新特性包括：

- **语义化标签**：如 `header`、`nav`、`article`、`section`、`footer`，使结构清晰、利于检索与无障碍访问。
- **原生多媒体**：`audio` 与 `video` 标签无需插件即可播放音视频。
- **图形绘制**：`canvas`（脚本逐像素绘制）与内联 `svg`（矢量图形）。
- **本地存储与离线能力**：`localStorage`、`sessionStorage` 持久保存数据，配合缓存机制支持离线访问。
- **设备能力访问**：地理定位、摄像头与麦克风调用、传感器事件。
- **增强的表单与响应式支持**：新的输入类型与校验属性，配合 CSS 媒体查询适配多终端。

制作与发布流程：规划页面结构与交互 → 编写 HTML 结构与 CSS 样式、JavaScript 交互 → 准备并适配多媒体资源 → 在多种浏览器与设备上测试兼容性与响应式效果 → 部署到 Web 服务器或静态托管平台，绑定域名并配置 HTTPS → 持续更新与性能优化。

> 关键提醒：HTML5 只是结构与标准，页面的视觉样式由 CSS 负责，交互逻辑由 JavaScript 负责，三者分工不能混淆。

## 七、虚拟现实技术

**基本概念**：虚拟现实（Virtual Reality，VR）是以计算机技术为核心，结合传感与显示设备，生成与真实环境高度相似的**数字化三维虚拟环境**，用户借助头显、手柄等设备与之交互，获得身临其境的体验。

**三大特征（3I）**：**沉浸性**（Immersion，多感官被虚拟环境包围）、**交互性**（Interaction，操作能实时改变虚拟场景）、**构想性**（Imagination，可构建现实不存在的情境）。

**相关概念的区分**：VR 完全替代现实视野；AR（增强现实）把虚拟信息叠加到真实场景上；MR（混合现实）使虚拟物体与真实环境实时融合并可交互；三者统称 XR（扩展现实）。

**发展历程**：20 世纪 60 年代出现带多感官模拟的实验装置；80 年代虚拟现实概念与数据手套等交互设备成型；2010 年代后消费级头显推动普及；近年向轻量化、无线化与空间计算演进。

**应用场景**：教育与实训（虚拟实验室、危险操作演练）、医疗（手术模拟、康复训练、心理治疗）、工业（数字样机评审、装配培训）、文旅（虚拟展馆、沉浸式演出）、军事（模拟训练）、房地产（样板间漫游）。

**未来趋势**：设备轻量化与舒适度提升、显示分辨率与视场角继续增强、手势与眼动等自然交互普及、内容生产借助 AI 大幅降本、与数字孪生和元宇宙场景结合。

**例 6.9-3** 某医学院要用系统训练学生在突发情况下的手术操作，允许反复练习且不消耗真实标本。最适合的技术是（　）。

A. 用 PDF 讲义代替实操
B. 构建 VR 手术模拟系统，支持力反馈与操作评分
C. 播放手术视频供学生观看
D. 用 Excel 记录操作步骤

**解**

1. 需求包含三点：可反复练习、零耗材风险、能训练操作技能而非仅记忆知识。
2. VR 手术模拟具备沉浸性与交互性，可配合力反馈还原手感并自动评分，故选 B。
3. A、D 只能传递或记录知识，无法训练动作技能；C 是单向观摩，缺乏交互与反馈。

- **易错点**：①把 VR 与 AR 混同，看"是否遮蔽真实环境"即可区分；②认为虚拟现实只用于娱乐，其在实训、医疗、工业领域价值更大；③把 3I 中的"构想性"误解为"想象力丰富的人更适合使用"。

## 本节小结

1. 数字媒体以二进制形式表示文本、图形图像、声音、视频与动画；数字媒体技术覆盖获取、压缩、编辑、存储、传输与呈现。
2. 数字文本处理为录入、编辑、排版、存储、检索，OCR 与语音识别是重要录入手段，编码统一可避免乱码。
3. 数字图像处理包括去噪、增强、复制、分割、特征提取、压缩、存储、检索；JPEG 有损、PNG 无损且支持透明。
4. 声音数字化三步为采样、量化、编码；数据量 = 采样频率 × 量化位数 × 声道数 × 时长 ÷ 8。
5. 数字视频处理为采集、剪辑、特效字幕、音频处理、压缩编码、输出发布；H.264/H.265 是主流编码，MP4 兼容性最好。
6. HTML5 新特性含语义化标签、原生音视频、canvas/svg、本地存储、设备能力访问；VR 的 3I 是沉浸性、交互性、构想性，VR 替代现实、AR 叠加现实、MR 融合现实。

7. **去噪**（图像去噪）。
8. **ABC**。D 错：JPEG 是有损压缩，舍弃部分视觉冗余信息，无法完全还原原始像素。
