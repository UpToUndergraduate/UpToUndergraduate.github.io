# 6.2 信息安全

> **考纲对应**：信息安全 第 1~8 条——建立安全意识并能识别网络欺诈；了解信息安全基本要素与网络安全等级保护；了解常见威胁、防御技术及安全设备的功能与部署；了解安全保障思路；掌握系统安全中心的防火墙与病毒防护配置；熟悉第三方安全工具的使用（层次：掌握 + 熟悉 + 了解）
> **教材对应**：单元 7 · 信息安全

信息安全是扩展模块中唯一同时要求"懂概念"和"会操作"的一节：既要能判断某种攻击属于哪类威胁、某台设备该部署在哪里，也要能在系统安全中心里把防火墙和病毒防护逐步配好。把"威胁—技术—设备—操作"四层对应起来，比零散背名词有效得多。

## 一、信息安全的基本概念

### 1. 基本要素

信息安全指保护信息及其载体免受偶然或恶意的破坏、篡改与泄露，保障系统连续可靠运行。核心是三要素，另有两个常考的扩展要素。

| 要素 | 含义 | 被破坏的后果 |
|---|---|---|
| 保密性 | 信息只被授权者获取 | 客户名单、病历被泄露 |
| 完整性 | 信息未被未授权篡改 | 转账金额、成绩被改 |
| 可用性 | 授权者需要时能正常使用 | 网站被打瘫、文件被加密 |
| 可控性 | 信息传播与操作可被掌控 | 违规内容无法追查 |
| 不可否认性 | 行为发生后无法抵赖 | 电子合同一方否认签署 |

判断要素看"损失的是什么"：被看到是保密性，被改是完整性，用不了是可用性，赖账是不可否认性。

### 2. 网络安全等级保护

等级保护是我国信息安全的基本制度，按系统被破坏后对国家安全、社会秩序、公共利益及公民权益的危害程度，由低到高分为五级：第一级自主保护、第二级指导保护、第三级监督保护、第四级强制保护、第五级专控保护。第二级以上需备案，第三级每年测评。工作环节为定级、备案、建设整改、等级测评、监督检查，技术要求见国家标准 GB/T 22239。

### 3. 安全意识

口令要长且不重复、定期更换；不点陌生链接与附件；重要数据定期备份并留离线副本；按最小权限授权；离开工位锁屏；不用来源不明的 U 盘与破解软件。大量安全事件并非技术被攻破，而是人先被攻破。

**例 6.2-1** 某学生接到自称"公安局"的电话，称其身份证被用于洗钱，要求添加社交账号接收"通缉令"并把资金转入"安全账户"自证清白。下列判断与处置最恰当的是（　）。

A. 对方能说出姓名与身份证号，说明身份可信，应照办
B. 公检法不会电话办案，更无"安全账户"，应挂断并向官方渠道核实
C. 先转一小笔试探，能退回再继续
D. 把卡号与短信验证码发给对方，请其协助"冻结"

**解**

1. 公检法办案会当面出示证件与文书，不会电话通知"涉嫌犯罪"并要求转账。
2. "安全账户"是典型诈骗话术，我国不存在此类账户；个人信息可能早已泄露，能报出姓名不代表身份可信。
3. 转账不可逆，"小额试水"同样会损失；验证码等同于支付密码，绝不能提供。
4. 正确处置是挂断、不添加账号、不下载其提供的软件，通过 110 或到派出所当面核实；已转账立即报警并联系银行止付。答案选 B。

- **易错点**：①把"知道我的信息"当成"官方身份"；②相信"先小额试探"安全；③把验证码当作身份核验工具交给对方。

## 二、常见威胁与网络欺诈识别

| 威胁 | 机理 | 典型现象 |
|---|---|---|
| 计算机病毒 | 寄生文件、依附宿主传播并破坏数据 | 文件异常、系统变慢、弹窗 |
| 蠕虫 | 利用漏洞自我复制，无需宿主 | 网络拥塞、大量扫描流量 |
| 木马 | 伪装正常程序，留下后门 | 账号被盗、被远程控制 |
| 勒索软件 | 加密文件索要赎金 | 扩展名被改、出现勒索信 |
| 钓鱼攻击 | 伪造可信身份骗取账号或财物 | 假冒银行、学校、快递的短信 |
| DDoS | 控制大量"肉鸡"耗尽目标资源 | 网站突然无法访问 |
| SQL 注入 | 输入中拼接恶意语句 | 数据库被拖走或篡改 |
| 跨站脚本 | 页面注入脚本窃取凭据 | 打开页面后账号异常 |
| 社会工程学 | 利用信任、恐惧、贪利心理行骗 | 冒充领导要求转账 |

前四类属恶意代码，钓鱼与社会工程学攻击的是"人"而非机器。

常见骗局有固定套路：冒充公检法称"涉嫌洗钱"；刷单返利先给小利再套本金；虚假投资平台先让提现后无法取出；冒充客服称"商品有问题要退款"，诱导提供验证码或开启屏幕共享；以"注销校园贷、修复征信"为名骗贷；用 AI 换脸拟声冒充亲友借钱。识别铁律是"不轻信、不透露、不转账、多核实"，凡要求转账到"安全账户"、索要验证码、要求屏幕共享或下载不明 App 的，一律终止并通过官方渠道回拨核实。

## 三、信息安全防御技术与设备

### 1. 常用防御技术

- **加密**：对称加密（如 AES）加解密同一密钥，速度快，适合大批数据，难点是密钥分发；非对称加密（如 RSA）公钥加密、私钥解密，或私钥签名、公钥验签，解决分发与认证问题，速度慢，常与对称加密配合。
- **完整性校验**：用哈希算法（如 SHA-256）计算摘要，内容稍改摘要即变。哈希不可逆，不能当加密用。
- **身份认证与访问控制**：口令、动态令牌、数字证书、生物特征，两类以上不同因素组合即双因子认证；权限按最小化原则分配并留审计。
- **备份与容灾**：至少保留一份离线副本，否则联网备份同样会被勒索软件加密。

### 2. 常用安全设备与部署

| 设备 | 主要功能 | 部署位置 |
|---|---|---|
| 防火墙 | 按规则过滤流量，隔离安全域 | 网络边界，串接 |
| IDS 入侵检测 | 监听流量、发现攻击并报警，不阻断 | 旁路（镜像端口） |
| IPS 入侵防御 | 检测并实时阻断 | 链路中串接 |
| WAF | 防 SQL 注入、跨站脚本、CC 攻击 | Web 服务器之前 |
| VPN | 建加密隧道，支持远程接入 | 网关或独立部署 |
| 堡垒机 | 集中管控运维账号、审计操作 | 运维终端与服务器之间 |
| 网闸 | 物理隔离网络间的受控数据交换 | 内外网隔离边界 |
| 日志审计 | 集中收集、留存、分析日志 | 旁路独立部署 |

防火墙有三种部署模式：路由模式（作网关串接，可做 NAT）、透明模式（网桥串接，不改拓扑）、旁路模式（只监听）。记牢"串接能阻断、旁路只能看"。

**例 6.2-2** 某单位网站频遭 SQL 注入与跨站脚本攻击，希望在攻击到达服务器前拦截，且不改动现有拓扑。最合适的方案是（　）。

A. 在镜像端口部署 IDS
B. 在 Web 服务器前以透明模式部署 WAF
C. 在服务器上安装杀毒软件
D. 在边界部署网闸

**解**

1. SQL 注入与跨站脚本属应用层攻击，包过滤防火墙与杀毒软件难以识别。
2. IDS 旁路只能发现报警，无法在到达服务器前阻断，不满足"拦截"。
3. WAF 解析 HTTP 内容，可识别并阻断此类攻击；透明模式串接不改拓扑。
4. 网闸用于强隔离网络间的受控交换，会使网站无法正常服务。答案选 B。

- **易错点**：①混淆 IDS 与 IPS 的部署方式与能力；②认为装了防火墙就万事大吉，它不查应用层内容，也不防内部违规与 U 盘传播；③把网闸当通用防护设备。

## 四、用系统安全中心配置防火墙与病毒防护

Windows 安全中心包含"防火墙和网络保护""病毒和威胁防护""账户保护""应用和浏览器控制"等模块。

### 1. 配置防火墙

1. 打开"设置—隐私和安全性—Windows 安全中心—防火墙和网络保护"。
2. 界面分列域网络、专用网络、公用网络三种配置文件。连接咖啡厅、机场等不可信网络时，应确保"公用网络"防火墙开启，其默认阻断的入站连接更多。
3. 点击"允许应用通过防火墙"，勾选允许通信的应用及适用配置文件；不对外提供服务的应用应取消勾选。
4. 需精细控制时进入"高级设置"，在"入站规则/出站规则"中按程序、端口或自定义条件新建允许或阻止规则，并指定作用域与配置文件。

**例 6.2-3** 某同学的笔记本要带到咖啡厅使用，希望禁止某下载工具接受外部入站连接，同时不影响自己上网。请说明操作要点。

**解**

1. 先把网络位置设为"公用网络"，确认该配置文件的防火墙已开启，这是不可信环境的基本防护。
2. 进入"允许应用通过防火墙"，找到该工具后取消其"公用"列勾选；列表中无此程序时先点"更改设置"。
3. 需更严格控制时，进入"高级设置—入站规则—新建规则—程序"，选中其可执行文件，操作选"阻止连接"，配置文件只勾"公用"。
4. 出站规则保持默认允许，配完用浏览器验证上网正常。修改规则需管理员权限，规则按配置文件分别生效。

- **易错点**：①忘改网络位置为"公用"；②误在"出站规则"中阻止程序，导致自己无法上网；③以为关闭防火墙能提速，实为放弃防护。

### 2. 配置病毒防护

1. 进入"病毒和威胁防护—管理设置"，确认"实时保护""云提供的保护"开启，实时保护是拦截恶意代码的第一道关口。
2. 主界面可选"快速扫描"，或在"扫描选项"中选"完全扫描"（全盘）、"自定义扫描"（指定目录）。
3. 发现威胁按提示"隔离"或"删除"；确属误报可加入"排除项"，但会降低防护强度，须谨慎。
4. 开启"勒索软件防护"中的"受控文件夹访问"，阻止未授权程序改动文档目录；同时保持系统更新，及时打补丁。

- **易错点**：①为"提升性能"长期关闭实时保护；②把下载目录整体加入排除项；③只装杀毒软件而不打补丁，漏洞型攻击仍可成功。

## 五、第三方安全工具与安全保障思路

第三方工具按用途分类：病毒查杀类（如火绒、卡巴斯基）、恶意软件专杀类、漏洞扫描类（如 Nessus、OpenVAS）、网络扫描类（如 Nmap）、抓包分析类（如 Wireshark）、密码管理类。使用要点有三：从官网下载，破解版本身常带毒；只装一款常驻杀毒软件，多款并存会互相拦截；扫描结果要人工判断，避免误删系统文件。

安全保障的一般思路是"管理、技术、人员"三管齐下，流程为：资产梳理与定级、风险评估、制度与策略制定、部署纵深防御、监测预警、应急处置、演练改进。业界用 PDRR 模型概括这一闭环：防护、检测、响应、恢复。其核心是承认"没有绝对的安全"，防护终会被突破，因此必须靠检测尽早发现、靠响应与恢复把损失控制在可接受范围。

- **易错点**：①把安全保障等同于"买设备"，忽视制度与培训；②有了防火墙和杀毒软件就不做备份；③把应急响应等同于"重装系统"，不做取证与原因分析。

## 本节小结

1. 信息安全三要素是保密性、完整性、可用性，扩展要素为可控性与不可否认性。
2. 等级保护分五级，环节为定级、备案、建设整改、等级测评、监督检查，二级以上备案、三级每年测评。
3. 病毒、蠕虫、木马、勒索软件属恶意代码；钓鱼与社会工程学攻击"人"，铁律是不轻信、不透露、不转账、多核实。
4. 对称加密快而密钥难分发，非对称加密解决分发与认证，哈希用于完整性校验且不可逆。
5. 设备部署记"串接能阻断、旁路只能看"：IDS 旁路报警，IPS 串接阻断，WAF 在 Web 服务器前，堡垒机管运维审计，网闸用于强隔离。
6. 安全中心要会按配置文件开关防火墙、设置应用与入站规则，并开启实时保护、执行扫描、启用受控文件夹访问；整体保障按 PDRR 闭环运行。

A. 钓鱼攻击　B. DDoS 攻击　C. SQL 注入　D. 蠕虫传播

A. 防火墙　B. WAF　C. 网闸　D. 堡垒机

8.（多选）下列关于信息安全保障的做法，正确的有
A. 重要数据定期备份，并保留离线副本
B. 按最小权限原则分配账号权限
C. 及时安装系统与软件安全补丁
D. 为方便记忆，所有网站使用同一个简单口令

### 参考答案

1. **C**。文件被加密导致无法使用，是可用性被破坏；A 指泄露，B 指篡改，D 指否认操作。
2. **B**。第二级及以上需备案，第一级为自主保护不备案。
3. **C**。IDS 旁路监听只告警，IPS 串接在链路中可阻断；A、B 说反，D 中应用层攻击主要由 WAF 防御。
4. **A**。伪造客服身份诱导点击链接、填写卡号与验证码，是典型钓鱼。
5. **C**。SHA-256 是哈希算法，不可逆；AES、RSA 可逆，Base64 只是编码。
6. **B**。WAF 解析 HTTP 内容，专防应用层攻击；防火墙看网络层，网闸做隔离，堡垒机管审计。
7. **B**。受控文件夹访问属勒索软件防护，限制未授权程序写入受保护目录。
8. **ABC**。D 错：多站共用简单口令，一旦泄露即引发撞库，所有账号同时失守，应使用互不相同的高强度口令。
