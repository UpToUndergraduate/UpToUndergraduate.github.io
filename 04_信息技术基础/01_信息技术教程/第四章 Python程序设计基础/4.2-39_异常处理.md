# 4.13 异常处理

> **考纲对应**：Python 程序设计基础 第 6 条——掌握 `try-except` 异常处理结构，能编写健壮的程序（层次：掌握）
> **教材对应**：Python 二级教程 · 第 4 章 程序的控制结构

再完善的程序也会遇到意外：用户输入了字母却要求转成整数，文件被误删，除数为零，列表下标越界。若不处理，程序会立刻中断并打印一大段红色报错；若处理得当，程序可以给出友好提示并继续运行。异常处理机制正是为此而生，它把"正常流程"与"出错补救"分开书写，使程序在意外面前保持可控。本节讲解异常的分类、`try-except-else-finally` 的完整结构、异常的抛出与捕获顺序，并强调"捕获该捕获的异常"这一工程原则。

## 一、异常的概念与常见类型

### 1. 语法错误与运行时异常

**语法错误（SyntaxError）**在程序运行前就会被解释器发现，属于"写错了"，只能修改代码；**异常（Exception）**则是语法正确但运行过程中出现的问题，可以被捕获和处理。二者性质不同：异常处理无法挽救语法错误，`try` 也包不住缩进错误。

异常在 Python 中也是对象，每个异常类都继承自 `BaseException`，常用异常则继承自 `Exception`。异常发生时，解释器创建一个异常对象，沿调用栈向上"抛出"，若无人捕获，程序终止并打印**回溯信息（traceback）**，其中最后一行给出异常类型与说明。

这种"类继承"的设计带来一个实用结论：捕获父类可以连带捕获子类。例如 `except Exception:` 能捕获几乎所有常见异常，而 `except ZeroDivisionError:` 只捕获除零。利用这一点可以写"兜底分支"，但兜底分支应放在最后，并且必须记录日志或给出提示，不能吞掉异常。

### 2. 常见异常类型

| 异常 | 触发场景 | 示例 |
|---|---|---|
| `ZeroDivisionError` | 除数为 0 | `10 / 0` |
| `ValueError` | 类型正确但值不合法 | `int("abc")` |
| `TypeError` | 类型不匹配 | `"1" + 1` |
| `IndexError` | 序列下标越界 | `[1, 2][5]` |
| `KeyError` | 字典键不存在 | `{"a": 1}["b"]` |
| `NameError` | 使用未定义的变量 | `print(x)` |
| `AttributeError` | 对象没有该属性或方法 | `"abc".push("d")` |
| `FileNotFoundError` | 打开的文件不存在 | `open("无.txt")` |

区分 `ValueError` 与 `TypeError` 是常考点：前者是"类型对、值不对"，如 `int("abc")`；后者是"类型本身就不对"，如 `1 + "a"`。`IndexError` 与 `KeyError` 同理，一个针对序列下标，一个针对字典键。

## 二、try-except 结构

### 1. 基本语法

```python
try:
    可能出错的语句
except 异常类型:
    出错后的处理
```

执行流程是：`try` 块中的语句正常执行完毕，则跳过 `except` 继续往下；一旦某条语句抛出指定类型的异常，`try` 块中其后的语句全部跳过，转去执行 `except` 块；若异常类型不匹配，则不被捕获，继续向上传播。这意味着 `try` 块中"出错点之后"的代码不会执行，编写时应把相互独立的操作分开放在多个 `try` 中，避免一处失败导致后续全部跳过。

### 2. 完整结构：else 与 finally

```python
try:
    result = 10 / int(input("除数："))
except ValueError:
    print("请输入整数")
except ZeroDivisionError as e:
    print("除数为零：", e)
else:
    print("结果：", result)
finally:
    print("程序结束")
```

四个子句各司其职：

| 子句 | 执行时机 | 典型用途 |
|---|---|---|
| `try` | 总是执行 | 放置可能出错的代码 |
| `except` | 发生匹配异常时执行 | 提示、记录日志、补救 |
| `else` | `try` 无异常时执行 | 放置"只有成功才做"的后续逻辑 |
| `finally` | 无论是否异常都执行 | 关闭文件、释放资源 |

`else` 的价值在于缩小 `try` 的范围：把"可能出错的一行"放进 `try`，把"依赖成功结果的后续处理"放进 `else`，避免后续代码的异常被误判为同一种错误。`finally` 则保证清理动作一定执行，即使 `try` 中有 `return` 或 `break`。

### 3. 捕获多个异常

一个 `try` 可以配多个 `except`，按书写顺序逐个匹配；也可在一个 `except` 中用元组并列多种类型：

```python
try:
    value = int("12a")
except (ValueError, TypeError) as e:
    print("转换失败：", e)
```

`as e` 把异常对象绑定到变量 `e`，可用 `str(e)` 或 `e.args` 取得错误信息。多个 `except` 时，**子类异常必须写在父类之前**，否则父类会先匹配，子类的分支永远不执行。

### 4. 主动抛出异常：raise 与 assert

除了被动捕获，程序也可以主动抛出异常，用于报告"参数不合法"等业务错误：

```python
def set_age(age):
    if not 0 < age < 150:
        raise ValueError("年龄必须在 1~149 之间")
    return age
```

`raise 异常类("说明")` 会创建并抛出异常对象。`assert 条件, "提示"` 是简化写法，条件为假时抛 `AssertionError`，多用于调试阶段的内部检查，正式发布时可用 `-O` 参数关闭。

**例 4.13-1**

编写一个除法函数，分别处理"输入非数字"与"除数为零"两种情况，并要求无论成功与否都输出结束提示。

**解**

1. 把 `int()` 转换与除法都放进 `try`，两者都可能抛异常。
2. 用两个 `except` 分别捕获 `ValueError` 与 `ZeroDivisionError`。
3. 用 `finally` 输出结束提示，验证其必然执行。

```python
def divide(a, b):
    try:
        result = int(a) / int(b)
    except ValueError:
        print("输入的不是整数")
    except ZeroDivisionError:
        print("除数不能为 0")
    else:
        print("结果：", result)
    finally:
        print("本次计算结束")

divide("10", "2")
divide("10", "0")
divide("abc", "2")
```

运行结果：

```
结果： 5.0
本次计算结束
除数不能为 0
本次计算结束
输入的不是整数
本次计算结束
```

**分析**：第一次调用走 `else` 分支，第二、三次走各自的 `except`，三次都执行了 `finally`。注意 `"10" / "2"` 若不做转换会抛 `TypeError`，这里先 `int()` 再相除，把类型问题统一归到 `ValueError` 分支。

- **易错点**：① `except` 后面不写类型等于捕获所有异常，会掩盖真正的 bug；② `except` 中只写 `pass` 会让错误"悄无声息"，排查极其困难；③ `finally` 中若有 `return`，会覆盖 `try` 中的返回值，务必慎用。

## 三、异常的传播与程序健壮性

### 1. 异常沿调用栈传播

函数内部未捕获的异常会传给调用者，逐层向上，直到被某个 `try` 捕获或到达程序顶层。因此可以"谁离问题近谁处理"，也可以"底层只管抛，顶层统一处理"。若最终无人处理，解释器打印 traceback 并终止程序，traceback 从上到下依次是"调用点"，最底部才是出错位置，读报错应先看最后一行。

读懂 traceback 是调试的基本功。它通常包含三部分：文件与行号（指出代码位置）、出错的源码行（指出具体语句）、异常类型与消息（指出错误性质）。若 traceback 中出现了自己没有写过的文件名，多半是第三方库内部抛出的异常，真正的原因仍在自己的调用参数上。

### 2. 捕获的原则

合理的异常处理遵循三条原则：**只捕获预期的类型**（如转换输入时捕获 `ValueError`）、**捕获后要有动作**（提示、重试、记录、转换默认值）、**不要把大段业务逻辑包进 `try`**（会导致异常来源难以定位）。捕获过宽（`except Exception`）虽然能让程序"不崩"，但也会把编程错误伪装成正常流程，属于典型的坏味道。

当内置异常不足以表达业务含义时，可以自定义异常类，只需继承 `Exception` 并写一行 `pass`：`class ScoreError(Exception): pass`，随后 `raise ScoreError("成绩格式错误")` 即可。自定义异常的类名通常以 `Error` 结尾，它的好处是调用方可以精确捕获"自己关心的问题"，而不会误伤其他错误。

### 3. 用异常做输入校验

交互程序的标准写法是"循环 + 异常"：只要输入不合法就提示重来，直到得到合法值。这样既不用写复杂的前置判断，也能覆盖所有非法输入。

**例 4.13-2**

要求用户输入 0 到 100 之间的成绩，输入非数字或超出范围时提示并重新输入，直到合法为止。

**解**

1. 用 `while True` 构成无限循环。
2. `try` 中做 `float()` 转换，捕获 `ValueError` 后 `continue` 重新输入。
3. 转换成功后用 `if` 检查范围，不合法则提示并继续，合法则 `break`。

```python
while True:
    text = input("请输入成绩（0~100）：")
    try:
        score = float(text)
    except ValueError:
        print("输入的不是数字，请重新输入")
        continue
    if not 0 <= score <= 100:
        print("成绩必须在 0 到 100 之间")
        continue
    break

print("录入成功：", score)
```

运行示例（`>` 表示用户输入）：

```
请输入成绩（0~100）：>abc
输入的不是数字，请重新输入
请输入成绩（0~100）：>120
成绩必须在 0 到 100 之间
请输入成绩（0~100）：>85.5
录入成功： 85.5
```

**分析**：`continue` 让循环回到开头重新输入，`break` 在合法时跳出。把"类型校验"交给异常、把"范围校验"交给 `if`，是因为前者可能抛异常、后者只是逻辑判断，职责分明。

**例 4.13-3**

读取文件 `data.txt`，若文件不存在则给出提示，而不是让程序崩溃。

**解**

1. 把 `open` 与读取放进 `try`。
2. 捕获 `FileNotFoundError`，输出友好提示。
3. 用 `with` 确保文件被关闭。

```python
try:
    with open("data.txt", "r", encoding="utf-8") as f:
        print(f.read())
except FileNotFoundError:
    print("文件 data.txt 不存在，请检查路径")
```

运行结果（文件不存在时）：

```
文件 data.txt 不存在，请检查路径
```

- **易错点**：① 捕获 `FileNotFoundError` 只能处理"文件不存在"，权限不足会抛 `PermissionError`；② 把 `open` 写在 `with` 外面捕获不到异常，顺序不能反；③ 捕获异常后仍继续使用未赋值的变量，会引发新的 `NameError`。

## 本节小结

1. 语法错误在运行前被发现，无法用 `try` 捕获；异常发生在运行时，可被捕获处理。
2. 常见异常需能对号入座：除零、下标越界、键不存在、值非法、类型不匹配、文件不存在。
3. `try-except-else-finally` 中，`else` 仅在无异常时执行，`finally` 无论是否异常都执行。
4. 多分支 `except` 按顺序匹配，子类异常必须写在父类之前；`as e` 可获取异常对象与信息。
5. `raise` 主动抛出异常，`assert` 用于调试断言；捕获后必须有实质处理动作。
6. 输入校验的标准套路是"循环 + try + continue/break"，避免宽泛捕获掩盖真正的错误。

### 参考答案

1. **B**。除数为 0 抛 `ZeroDivisionError`；`ValueError` 对应值非法，`TypeError` 对应类型不匹配。
2. **C**。`"abc"` 是字符串类型正确，但内容无法转为整数，属于值不合法，抛 `ValueError`。
3. **C**。`finally` 用于资源清理，无论 `try` 是否抛异常、是否 `return`，都会执行。
4. **A**。`try` 中无异常，`print("A")` 后跳过 `except`，执行 `else` 输出 `C`，最后 `finally` 输出 `D`。

6. **错误**。语法错误在编译阶段就被发现，程序根本无法开始运行，`try` 无法捕获。
7. 参考代码：

```python
total = 0

    text = input("请输入整数（输入 0 结束）：")

    if num == 0:

print("累加和：", total)
```

也可用 `text.lstrip("-").isdigit()` 先判断再转换，但异常写法更简洁，且能覆盖 `" 12 "` 等带空格的合法输入。
