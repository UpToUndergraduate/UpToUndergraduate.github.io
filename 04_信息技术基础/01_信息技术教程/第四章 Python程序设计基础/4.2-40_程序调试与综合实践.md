# 4.14 程序调试与综合实践

> **考纲对应**：Python 程序设计基础 第 7 条——掌握 Python 程序的编写和调试方法，能综合运用所学知识完成小型程序（层次：掌握）
> **教材对应**：Python 二级教程 · 第 1 章 程序设计基本方法

前面各节分别讲解了语法、流程控制、数据类型、函数、文件与异常，但真实的任务从不按章节出牌：一个成绩统计程序可能同时用到列表、字典、函数、文件与异常处理。能否把这些零件组装成可运行、可维护、可排错的程序，正是考纲第 7 条要检验的能力。本节先梳理程序编写的一般流程与代码规范，再系统介绍三类错误的定位方法，最后用一个综合案例走完"设计—编码—测试—修正"的全过程。

## 一、程序的编写流程与规范

### 1. 从问题到程序

编写程序不是"打开编辑器就敲代码"，规范的流程包含四步：

1. **分析问题**：明确输入是什么、输出是什么、有哪些边界情况（空数据、非法输入、极值）。
2. **设计算法**：用自然语言或流程图写出步骤，确定数据结构（用列表、字典还是文件）。
3. **编码实现**：把步骤翻译为语句，先搭骨架再填细节，每完成一小块就运行验证。
4. **测试修正**：用正常数据、边界数据、异常数据各测一遍，发现偏差就回到第 2 步。

初学者最容易跳过第 1、2 步，直接写出一大段代码再一次性运行，结果面对一屏报错无从下手。正确策略是"小步快跑"：每次只增加几行，运行通过后再继续，出错范围就被压缩在最近几行之内。

### 2. 代码规范

可读的代码更容易调试。二级考试虽不强制评分风格，但以下习惯能显著减少低级错误：

- 变量名用有含义的英文或拼音，如 `total_score` 而非 `a1`；常量全大写。
- 每行只做一件事，函数控制在 30 行以内，一个函数只承担一个职责。
- 关键逻辑写注释，说明"为什么这样做"，而不是重复"这行在做什么"。
- 缩进统一用 4 个空格，不混用 Tab；运算符两侧留空格。
- 输入一律用 `strip()` 清洗，数值转换一律考虑异常。

### 3. 三种结构的综合运用

任何复杂程序都可以拆成顺序、分支、循环三种结构的组合。经验做法是：**主流程用顺序结构串联，判断用分支，重复用循环，复杂步骤封装成函数**。当发现循环里嵌套了三层 `if`，通常说明该把内层逻辑提取成函数了。

## 二、程序的调试方法

### 1. 三类错误

| 错误类型 | 产生原因 | 表现 | 定位手段 |
|---|---|---|---|
| 语法错误 | 拼写、括号、冒号、缩进不规范 | 程序无法运行，提示 `SyntaxError` | 看报错行号，检查上一行末尾 |
| 运行时错误 | 除零、越界、类型不符、文件缺失 | 运行中途终止并打印 traceback | 看 traceback 最后一行 |
| 逻辑错误 | 算法写错、条件写反、变量未更新 | 能运行但结果不对，不报错 | 打印中间值、手工推演、对比预期 |

三类错误中，逻辑错误最难发现，因为程序"看起来没问题"。它不会抛异常，只能靠测试数据暴露。

### 2. 常用调试手段

1. **打印中间结果**：在关键位置插入 `print(变量名, 类型)`，确认值是否符合预期。这是最原始也最有效的方法，尤其适合循环中的状态追踪。
2. **阅读 traceback**：从最后一行往前读，先确定异常类型，再定位到自己的代码行。`IndexError` 提示下标算错，`TypeError` 提示类型不符，`NoneType` 往往意味着函数忘了 `return`。
3. **断言检查**：在可疑处写 `assert 条件, "提示"`，条件不成立立即中断，把问题挡在发生现场。
4. **断点调试**：在集成开发环境中于行号处设置断点，逐行执行并观察变量面板，可精确看到每一步的值如何变化。
5. **缩小范围**：把可疑代码单独复制到新文件，用最小数据复现，排除无关因素的干扰。
6. **单元测试**：为每个函数准备几组"输入—预期输出"，改动代码后重跑，防止"改好一处、改坏另一处"。

### 3. 常见逻辑错误的典型症状

| 症状 | 可能原因 | 排查方向 |
|---|---|---|
| 程序卡住不结束 | 循环条件永远为真、变量未更新 | 检查循环变量是否在循环体内改变 |
| 结果少一项或多一项 | 差一错误（`<` 与 `<=` 混用、切片终点） | 检查边界与 `range` 的终点 |
| 累加结果偏小 | 初值写错、首项被跳过 | 检查 `range` 起点与初值 |
| 输出全是 `None` | 原地方法返回值被赋值、函数缺 `return` | 检查赋值语句右侧 |
| 字符串与数字比较报错 | 输入未转换类型 | 检查 `input()` 后是否 `int()` |

**例 4.14-1**

下面的函数用于求一组成绩的平均分，但运行结果与预期不符。指出其中的错误并改正。

```python
def average(scores):
    total = 0
    for i in range(1, len(scores)):
        total += scores[i]
    return total / len(scores)

print(average([88, 92, 76]))
```

**解**

1. 手工推演：`range(1, 3)` 只取下标 1、2，首元素 88 被跳过，累加得 168。
2. 除数是 `len(scores)` 即 3，于是结果为 56.0，而正确值应为 85.33。
3. 定位到两处问题：循环起点错误（差一错误）、缺少空列表保护。

```python
def average(scores):
    if not scores:              # 增加空列表保护，避免除零
        return 0
    total = 0
    for score in scores:        # 直接遍历元素，避免下标错误
        total += score
    return total / len(scores)

print(average([88, 92, 76]))    # 85.33333333333333
print(round(average([88, 92, 76]), 2))   # 85.33
print(average([]))              # 0
```

**分析**：这类"能运行、结果不对"的错误属于逻辑错误，不会报错，只能靠对照预期值发现。修改时优先改结构（改为直接遍历元素），而不是打补丁（把 `range(1, ...)` 改成 `range(...)`），因为结构正确的代码不会再次踩到同类坑。

- **易错点**：① 用 `while i <= len(lst)` 遍历列表必然越界，正确边界是 `< len(lst)`；② 空列表求平均会抛 `ZeroDivisionError`，必须单独判断；③ 修改后只测一组数据不够，应补测空列表、单元素、含负数等情况。

## 三、综合实践：成绩统计程序

### 1. 需求与设计

要求读入一行"姓名:成绩"形式的文本，统计有效记录的人数、平均分、最高分与最低分，按成绩降序打印，并把结果写入 `result.txt`。设计要点：用 `partition(":")` 拆分每条记录，用字典保存"姓名→成绩"，用 `try` 过滤非法成绩，用 `sorted` 配合 `key` 排序，用 `with open` 写文件。

### 2. 编码实现

**例 4.14-2**

按上述需求编写完整程序，输入为 `"张三:88, 李四:95, 王五:abc, 赵六:76"`。

**解**

1. 写解析函数 `load_scores`，逐条拆分并转换，非法记录跳过并提示。
2. 写输出函数 `report`，处理空数据并格式化打印。
3. 主流程调用两个函数，最后把结果写入文件。

```python
def load_scores(text):
    """把 '姓名:成绩' 形式的文本解析为字典，非法记录跳过"""
    scores = {}
    for item in text.split(","):
        name, sep, value = item.partition(":")
        if not sep:                       # 没有冒号，格式错误
            print("跳过格式错误的记录：", item.strip())
            continue
        try:
            scores[name.strip()] = float(value)
        except ValueError:
            print("跳过成绩非法的记录：", item.strip())
    return scores


def report(scores):
    if not scores:
        print("没有有效成绩")
        return
    average = sum(scores.values()) / len(scores)
    best = max(scores, key=scores.get)
    worst = min(scores, key=scores.get)
    print("有效人数：%d，平均分：%.1f" % (len(scores), average))
    print("最高分：%s（%.0f），最低分：%s（%.0f）"
          % (best, scores[best], worst, scores[worst]))
    for name, score in sorted(scores.items(), key=lambda x: x[1], reverse=True):
        print("%-6s%6.1f" % (name, score))


data = "张三:88, 李四:95, 王五:abc, 赵六:76"
scores = load_scores(data)
report(scores)

with open("result.txt", "w", encoding="utf-8") as f:
    for name, score in scores.items():
        f.write("%s,%.1f\n" % (name, score))
print("结果已写入 result.txt")
```

运行结果：

```
跳过成绩非法的记录： 王五:abc
有效人数：3，平均分：86.3
最高分：李四（95），最低分：赵六（76）
张三        88.0
李四        95.0
赵六        76.0
结果已写入 result.txt
```

**分析**：这段程序把"解析""统计""输出""保存"分成独立步骤，每步都可单独测试。`partition` 与 `split(":")` 的区别在于前者无论是否找到分隔符都返回三元组，便于判断格式是否合法。`max(scores, key=scores.get)` 利用字典的 `get` 方法按值取键，是取"最高分姓名"的简洁写法。

### 3. 测试与改进

测试至少覆盖四类数据：正常数据（如上例）、全部非法（应输出"没有有效成绩"）、空字符串（`split` 得到 `[""]`，会被格式检查拦下）、含中文冒号或多余空格（`strip` 能处理空格，中文冒号需额外替换）。改进方向包括：支持从文件批量读入、把结果按班级分组、增加重复姓名的处理（如累加或提示覆盖）。每次改进后重跑全部测试用例，就是最朴素的回归测试。

- **易错点**：① 直接用 `split(":")` 后取 `parts[1]`，遇到无冒号的记录会抛 `IndexError`；② `scores.get` 作 `key` 时不能写成 `scores.get()`，函数对象与调用结果不同；③ 写文件时忘记 `encoding="utf-8"`，中文在 Windows 下可能乱码。

## 本节小结

1. 编写程序遵循"分析问题—设计算法—编码实现—测试修正"四步，坚持小步运行、及时验证。
2. 语法错误无法运行、运行时错误中途终止、逻辑错误结果偏差，三者的定位手段各不相同。
3. 调试的基本手段有打印中间值、阅读 traceback、断言、断点、缩小范围与单元测试。
4. traceback 应看最后一行确定异常类型，再回溯到自己的代码行。
5. 常见逻辑错误集中在边界条件、循环变量更新、初值与返回值，应重点检查。
6. 综合程序应拆成职责单一的函数，先保证每步正确，再串联成完整流程，并用多组数据回归测试。

A. 断点会让程序无法运行　B. 断点可让程序暂停在指定行，便于查看变量　C. 断点只能设置一个　D. 断点等同于 `print`

6.（判断）逻辑错误的程序一定会在运行时报错并终止。（　）

7.（编程）下面的程序本想求 1 到 100 之间所有偶数之和，但结果是 2450。请指出错误、改正代码并给出正确结果。

```python
i = 1
total = 0
while i < 100:
    if i % 2 == 0:
        total += i
    i += 1
print(total)
```

8.（多选）关于程序调试与编写，下列说法正确的是（　）。
A. 在关键位置打印变量值可以帮助定位逻辑错误
B. 为函数准备多组"输入—预期输出"用例，改动后可快速回归验证
C. 只要程序能运行且不报错，就说明逻辑一定正确
D. 把大段代码一次性写完再运行，比小步运行更容易定位错误

### 参考答案

1. **C**。循环条件写反不会报错，只是结果不对，属于逻辑错误；A 为语法错误，B、D 为运行时错误。
2. **B**。`IndexError` 专指序列下标越界；除零对应 `ZeroDivisionError`，键不存在对应 `KeyError`。
3. **C**。traceback 最后一行给出异常类型与消息，是判断错误性质的关键，其余部分用于回溯调用路径。
4. **B**。断点让程序在指定行暂停，可逐行执行并观察变量，与 `print` 的"事后打印"不同。
5. `assert`；traceback（回溯）。`assert` 条件为假时抛 `AssertionError`。
6. **错误**。逻辑错误不会抛异常，程序能正常结束，只是输出与预期不符，必须靠测试数据发现。
7. 错误在于循环条件 `i < 100` 漏掉了 100 本身，属于边界错误（差一错误）。改正为：

```python
i = 1
total = 0
while i <= 100:
    if i % 2 == 0:
        total += i
    i += 1
print(total)
```

输出 `2550`。也可直接用 `sum(range(2, 101, 2))` 验证：2 到 100 共 50 个偶数，和为 2550。

8. **AB**。C 错：程序不报错只说明没有语法和运行时错误，逻辑仍可能出错；D 错：一次性写完大段代码会让错误相互掩盖，小步运行才能把问题压缩在最近改动范围内。
